# MindForge AI 手动压力测试指南

> 目的：以"攻击性测试"思维，最大化发现项目中的隐藏 Bug  
> 方法：边界值、异常路径、竞态条件、状态污染、数据持久化、跨功能交互  
> 时间：完整执行约 2-3 小时

---

## 测试前准备

### 环境检查清单

- [ ] `npm test` 全部通过（当前 236 用例）
- [ ] `npm run build` 构建成功
- [ ] 浏览器 DevTools → Console 面板打开（监控错误）
- [ ] 浏览器 DevTools → Network 面板打开（监控 API 请求）
- [ ] 浏览器 DevTools → Application → Local Storage 查看 `mindforge-projects` 和 `mindforge-settings`
- [ ] 关闭浏览器缓存（DevTools → Network → Disable cache）

## 第五阶段：JSON 解析器压力测试（20 分钟）

> 核心痛点：AI 返回的 JSON 格式脆弱性

### 5.1 JSON 格式异常模拟

在 `jsonExtractor.ts` 中自动处理以下情况，手动测试可构造输入：

| #     | 模拟场景                                            | 触发方式          | 预期               |
| ----- | --------------------------------------------------- | ----------------- | ------------------ |
| 5.1.1 | AI 返回 markdown 代码块包裹 `\`\`\`json ... \`\`\`` | 正常考核流程      | 能正确提取 JSON    |
| 5.1.2 | JSON 末尾有多余逗号 `{...,}`                        | 手动修改返回 mock | 模糊解析器修复     |
| 5.1.3 | 单引号代替双引号 `{'key': 'value'}`                 | 同 5.1.2          | 正则替换修复       |
| 5.1.4 | 字段名无引号 `{key: "value"}`                       | 同 5.1.2          | JS 对象式解析      |
| 5.1.5 | 嵌套 JSON 中混有换行符和 Tab                        | AI 返回复杂格式   | 解析器健壮性       |
| 5.1.6 | 返回空 JSON `{}`                                    | AI 未生成有效题   | fallback 到默认值  |
| 5.1.7 | 返回不完整 JSON（截断）                             | 模拟 API 中断     | 多层 fallback 机制 |

### 5.2 手动测试方法

````javascript
// 在浏览器 Console 中执行（需要项目源码在调试状态）
// 定位到 jsonExtractor 模块，调用 extractJSON 函数

// 测试 1：标准 JSON
extractJSON('{"key": "value"}');

// 测试 2：markdown 包裹
extractJSON('```json\n{"key": "value"}\n```');

// 测试 3：单引号
extractJSON("{'key': 'value'}");

// 测试 4：末尾逗号
extractJSON('{"key": "value",}');

// 测试 5：无引号 key
extractJSON('{key: "value"}');

// 测试 6：空字符串
extractJSON("");

// 测试 7：非 JSON 纯文本
extractJSON("这是一段纯文本，不是JSON");
````
